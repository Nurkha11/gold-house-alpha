# Архитектура

## Карта каталогов

```text
app/          файловые маршруты и экраны Expo Router
components/   переиспользуемые UI-компоненты и web-карта
constants/    тема, цвета, отступы, радиусы, тени
data/         каталог объектов, типы и локальные хранилища/алгоритмы
scripts/      автономные Node.js проверки наборов данных и потоков
outputs/      самостоятельные HTML-превью
docs/         техническая документация
```

Точка входа задаётся `main: expo-router/entry`. Корневой layout — `app/_layout.tsx`: `GestureHandlerRootView`, `StatusBar` и общий `Stack`.

## Слои

1. Экраны читают URL-параметры Expo Router и вызывают функции `data/*Store.ts`.
2. Компоненты получают данные и callbacks через props.
3. `propertyStore.ts` объединяет локальный каталог с опубликованными заявками собственников.
4. `aiTrainingStore.ts` хранит активные фильтры/сигналы и рассчитывает рекомендации.
5. `buyerProfileStore.ts` дублирует сигналы в память покупателя и сохраняет их в `localStorage` на web.
6. `ownerStore.ts` и `adminStore.ts` работают в памяти процесса.

## Поток данных покупателя

Параметры маршрута → `startTrainingSession()` → жёсткие фильтры → обучающий поток → `recordTrainingSignal()` → эвристический score → три рекомендации. Сигналы также записываются в профиль покупателя.

## Навигация

Используется файловая маршрутизация Expo Router. Явной схемы route guards нет. Админские экраны выполняют клиентскую проверку телефона/состояния, но маршрут остаётся доступным клиентскому bundle.

## Хранение состояния

- каталог: статический TypeScript;
- buyer memory: `localStorage` на web, память процесса на native;
- обучение: память процесса;
- собственники, заявки и статусы: память процесса;
- admin session: boolean в памяти.

Перезагрузка приложения сбрасывает почти всё, кроме buyer memory в web.
