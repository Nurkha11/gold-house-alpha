# Модель данных

## Property

Определена в `data/properties.ts`. Обязательные поля включают ID, заголовок, город, район, ЖК, адрес, цену, комнаты, площадь, этажи, год, материал, ремонт, мебель, технику, балкон, лифт, парковку, высоту потолка, Match %, изображение, описание, теги, AI-резюме, плюсы, минусы, целевую аудиторию, причину продажи, время просмотра и текст локации. Часть медиа и данных владельца опциональна.

Каталог содержит 69 тестовых ID. Источник — локальный массив; опубликованные заявки преобразуются функцией `submissionToProperty()`.

## Buyer

`buyerProfileStore.ts` хранит профили, анонимную сессию, предпочтения и события: LIKE, DISLIKE, VIEW_DETAILS, LONG_VIEW_DETAILS, CALL_OWNER, SCHEDULE_VIEWING, SAVE, FINAL_RECOMMENDATION. Событие содержит snapshot объекта, что защищает историю от части изменений каталога.

## Owner submission

`PropertySubmission` содержит владельца, статус, адрес/локацию/ЖК, характеристики, цену и условия, состояние, текст владельца и media. Статусы: draft, submitted, reviewing, needs_shooting, approved, published, rejected.

## Location

`PropertyLocation` содержит нормализованный адрес, координаты, источник (`yandex`, `coordinates`, `manual`), источник района, точность публикации и предупреждения. Новый ЖК имеет отдельный moderation status и список возможных дублей.

## Расхождения

- цена и числовые поля заявки хранятся строками, а `Property` — числами;
- опубликованному объекту присваиваются фиксированные Match 96 и Trust Index 98;
- часть fallback-значений создаётся при публикации;
- реальной схемы БД, миграций и серверной валидации нет.
